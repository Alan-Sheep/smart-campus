# 用户端功能修复报告

> 针对用户反馈的 6 项缺陷，全部定位根因并修复，随后做了多校多轮回归测试。

---

## 一、6 项缺陷的根因与修复

### ① 校园频道帖子分类（吐槽/交友/分享）没有实现

**根因（两层）**
- `post` 表**根本没有 `category` 字段** —— 分类筛选无从谈起
- 前端 `switchTab()` 只是把 tab 高亮切了，**没有任何筛选参数传给后端**

**修复**
- `post` 表新增 `category VARCHAR(16)`（`推荐/吐槽/交友/分享`），并建复合索引 `(school_id, category, create_time)`
- 后端 `postList` 接受 `category` 参数做**服务端筛选**；「推荐」等价于全部
- 发布接口对 category 做**白名单校验**，非法值归为「推荐」
- 前端：发布弹窗新增**分类选择器**（默认跟随当前所在分类）；`switchTab` 传分类

### ② 评论后列表评论数不刷新

**根因**：uni-app 页面是 keep-alive 的，`onMounted` 只执行一次。
从帖子详情返回频道列表时**不会重新拉数据**，所以看到的还是旧数字。

**修复**
- `channel.vue` 增加 `onShow` 钩子：首次由 `onMounted` 加载，之后每次返回页面都刷新
- 详情页发表评论后同时刷新 `loadComments()` 和 `loadDetail()`，页内数字即时更新
- 后端 `postDetail` 补充返回 `commentCount`（原先只在列表里统计）

### ③ 私聊消息没有算在互动消息里

**根因**：私聊只写 `chat_message` 表，「互动消息」读的是 `message` 表（type=2），
两条链路完全不相干 → 私聊在互动消息里**完全不可见**。

**修复**
- `sendChat` 时**同步给接收方写一条 type=2（互动消息）记录**：
  标题为「XX 给你发了一条私信」，`relatedId` 指向发送者、`relatedType='chat'`
- 私信会自然出现在「互动消息」列表并计入未读数 ✓
- 修正 `unreadCount` 的 total 计算：**不再叠加 chat**（否则同一私聊会被算两次）

### ④ 帖子没有收藏功能

**根因**：数据库**没有收藏表**；`collection.vue` 是占位空壳；帖子详情无收藏入口。

**修复**
- 新建 `collect` 表（`user_id + target_id + target_type` 唯一索引，支持商品/帖子/活动）
- 新增后端接口：`POST /api/channel/collectPost`（切换收藏）、`GET /api/channel/myCollects`
- 帖子**列表和详情都返回 `isCollected`**，前端按钮能正确显示已收藏状态
- 详情页新增「点赞 / 收藏」操作栏；「我的收藏」页改为真实数据（可取消收藏）

### ⑤ 我的打印切状态报「参数格式不正常：status」

**根因**：`my-list.vue` 传的状态是**字符串** `'pending'/'progress'/'done'/'cancel'`，
而后端 `@RequestParam Integer status` 要数字 → 直接 400。

**修复**
- 状态选项的 value 全部改为**后端真实数字**（1待接单 2已接单 3已完成 4已取消 5已退款）
- 同时修正状态**文案映射**：原先前端自造了一套 0/1/2/3，与后端返回值对不上会显示「未知」
- 顺带发现并修复：**打印取消订单写的是 `status=0`，而约定是 `4=已取消`**，导致「已取消」列表查不到刚取消的订单

### ⑥ 我的快递：我发布/我接单不分，子分类不生效

**根因（三个，叠加）**
1. `expressApi.getMyOrders` **写死了 `type:'publish'`**，调用方传什么都被忽略
2. 前端角色值是 `'accept'`，但快递后端约定的是 **`'pick'`** —— 传 `'accept'` 落到 else 分支，返回**全部订单**
3. 状态筛选传的是字符串 `'pending'` 等，同样触发 400

**修复**
- API 层透传调用方的 type（不再写死）
- `my-list.vue` 按模块正确映射角色：快递 `accept→pick`，跑腿/代课用 `accept`
- 状态选项改数字 + 文案映射修正（并注明各模块 API 层是否做过 adapt 转换，避免踩坑）

## 六、第二轮反馈的 5 项问题

### 1. 帖子收藏：取消后再收藏报「数据保存失败」

**根因**：`collect` 表有 `(user_id, target_id, target_type)` 唯一索引，
但实体继承了 `deleted` 字段启用逻辑删除 —— `removeById` 只是把 `deleted` 置 1，
**唯一索引仍占用该行**，再收藏触发 Duplicate entry。

**修复**：`Collect` 实体去掉 `deleted` 字段（不做逻辑删除），取消收藏改用
`collectMapper.deleteById()` **物理删除**。实测连点 6 次状态正确切换、无残留。

### 2. 私聊消息即时性不够

**根因**：后端数据是即时的（A 发出后 B 立即查库就能查到），
但前端聊天页**只加载一次**，没有轮询/WebSocket，B 必须手动刷新才能看到。

**修复**（项目未引入 WebSocket，采用轮询兜底）：
- `chat.vue`：每 3 秒增量拉取最新消息，对比本地最新消息 id，有新消息才合并并滚动到底
- `message.vue`：每 5 秒刷新未读数，让「互动消息/聊天」角标保持最新
- 都做了 `onShow`/`onHide` 生命周期管理：页面隐藏暂停轮询、显示恢复，避免后台空耗

### 3. 快递/打印「我发布的」「我接单的」各账号显示一样

**排查结论：后端数据隔离是正确的**（用两个账号实测，SQL 查询只返回各自的订单）。
问题出在**前端两个页面没把筛选参数传给后端**：
- `express.vue` 的「我的订单」页签**根本没传 type**，也没传 status → 显示全部
- `my-list.vue` 虽有 tab，但传的角色值 `'accept'` 与快递后端约定的 `'pick'` 不匹配

**修复**：`express.vue` 的「我的订单」新增**两排子筛选**（我发布的/我接单的 + 状态条），
并把 `type` 与 `status` 传给后端；`my-list.vue` 的角色映射与状态值此前已修正。
实测：A 发布 2 单、B 发布 1 单，A 只看到自己的 2 单、B 只看到自己的 1 单，互不混淆。

> 注意：订单按 `school_id` 隔离，**接单人必须与订单同校**才能在「我接单的」里查到，
> 这是业务设计而非 bug。

### 4. 「示例大学」切走后切不回来

**根因**：历史版本把默认学校写死为 `{id:1, name:'示例大学'}` 并缓存在本地。
学校数据改名后，缓存的名称与列表对不上 → 按名称匹配不到。

**修复**：
- `App.vue`：默认学校改为「重庆大学」，并兼容旧缓存（检测到「示例大学」自动纠正）
- `store/school.js` 的 `setSchoolList`：加载学校列表后**按 id 校正缓存**——
  名称过期就同步最新名称；学校不存在就回退到列表第一个

### 5. 切换学校后游戏搭子分类只剩「全部」，发布的游戏名变成随手输的值

**根因（三个，叠加）**
1. `game_buddy` 的**数据全挂在 school_id=1**，切到其他学校 `gameTypes` 返回空 → 分类只剩「全部」
2. 切换学校后 `game.vue`/`game/publish.vue` **没有重新加载分类**（onMounted 只跑一次）
3. `game.vue` 的列表页此前对后端返回的**字符串数组**按对象属性取值（`g.name`）取不到，
   导致 `gameName` 变成空/乱填

**修复**
- `game/publish.vue` 归一化后端返回的字符串数组为 `{id,name}`
- `game.vue`、`game/publish.vue` 增加 `onShow`：切换学校返回时重新拉取本校分类
- `game_buddy` 为每所学校补齐 5 个游戏分类的示例数据（幂等，不重复插入）
- 清理了 `game_name` 为纯数字的脏数据

## 八、第三轮：同校隔离补全 + 注册选学校

### 1. 「同校隔离」发现实现不完整

**排查结论**：4 个订单模块的行为**并不一致**——

| 模块 | 大厅(hallList) 按 school 过滤 | 我的列表(orderList) 按 school 过滤 |
|---|---|---|
| 跑腿 errand | ✅ | ✅ |
| 代课 substitute | ✅ | ✅ |
| 快递 express | ✅ | ❌ **漏了** |
| 打印 print | ❌ 无大厅接口 | ❌ **漏了** |

所以「接单人必须与订单同校才能在『我接单的』查到」这个设计，
实际上**只有跑腿和代课真正生效**，快递和打印没有。

**修复**：给 `ExpressController.orderList` 和 `PrintController.orderList`
补上 `school_id` 过滤，四个模块行为统一。

**验证**（两个真实账号、分属 school1/school2）：
- 会话A（school1）：「我发布的」20 条，**非本人 0 条、非本校 0 条** ✅
- 会话B（school2）：「我发布的」1 条，**非本人/非本校 0 条** ✅
- 打印同理，隔离正确 ✅

### 2. 注册（首次登录）没有选择学校的入口

**现状**：本项目没有独立注册接口，**首次登录即注册**（自动建用户），
新建用户的 `school_id` 为 NULL → 发布的内容缺少学校归属。

**修复**
- 后端 `PUT /api/user/info` 放开 `schoolId` 字段的更新（原先只允许 nickname/avatar/phone）
- 前端 `login.vue`：登录成功后若 `userInfo.schoolId` 为空，**跳转学校选择页引导选校**
- 前端 `school.vue`：选校时若用户尚未绑定，**调用 updateUserInfo 把学校归属写回账号**
  （只在未绑定时回写，避免用户日常切换学校时覆盖原归属）

**验证**（模拟新用户完整流程）：
1. 首次登录 → `school_id = NULL` ✅
2. 选择重庆邮电大学(id=3) → `school_id = 3`（DB 铁证）✅
3. `/user/info` 返回 `schoolId=3` ✅
4. 发布订单、能在「我发布的」查到 ✅

> 老用户（在学校绑定功能上线前注册的）`school_id` 本来就是 NULL，
> 下次登录时会被引导选一次学校，属于预期行为。
