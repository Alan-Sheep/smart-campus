## 二、你反馈的两个问题，根因均已定位并实证

### 问题 1：所有业务的「发布」都报错

**根因（两类，叠加发生）**

**① 必填字段未提供 → MySQL 严格模式拒绝插入**

MyBatis-Plus 默认 `NOT_NULL` 策略会把 **null 字段从 INSERT 语句中省略**；
而数据库里那些列是 `NOT NULL` 且**无默认值**，于是报
`Field 'xxx' doesn't have a default value`。

| 模块 | 缺失的必填列 |
|---|---|
| 跑腿 errand | `receiver_name`、`total_amount` |
| 快递 express | `total_amount` |
| 打印 print | `file_urls`、`delivery_address`、`receiver_name`、`receiver_phone`、`total_amount`（5 个全缺） |
| 游戏搭子 game | `title` |

打印模块还叠加**字段名写错**——Jackson 默认忽略未知字段，所以错名被**静默丢弃**：
`fileUrl`→`fileUrls`、`address`→`deliveryAddress`、`phone`→`receiverPhone`、`price`→`totalAmount`。

**② 字符串写进 TINYINT 列 → MySQL 1366**

实体字段是 `String`，数据库列是 `TINYINT`，前端传的是人类可读字符串：

| 模块 | 字段 | 前端传 | 实测报错 |
|---|---|---|---|
| 打印 | `print_type` | `'document'` | `Incorrect integer value` |
| 失物招领 | `type` | `'lost'` | 同上 |
| 意见反馈 | `type` | `'suggestion'` | 同上 |
| 聊天 | `msg_type` | `'text'` | 同上 |

**③ 评论外键冲突**：`comment.parent_id` 列默认值为 `0`，但存在外键
`fk_comment_parent → comment(id)`，并不存在 id=0 的行 →
`Cannot add or update a child row: a foreign key constraint fails`。

### 问题 2：所有业务的「接取」都报错

**根因：参数传递方式不匹配**

- 后端 14 个操作接口写的是 `@RequestParam Long id`（**只吃 query/form 参数**）
- 前端 `utils/request.js` 统一用 `Content-Type: application/json` + **JSON body** 发送

实测对照（同一个接口，仅传参方式不同）：

```
POST /api/errand/acceptOrder   body={"id":1}   →  HTTP 400  ❌
POST /api/errand/acceptOrder?id=1              →  HTTP 200  ✅
```

日志实证：`MissingServletRequestParameterException: Required request parameter 'id' ... is not present`

受影响接口（14 个）：跑腿 accept/complete/cancel、快递 pick/complete/cancel、
代课 accept/cancel、打印 cancel、活动 signup/cancelSignup、频道 likePost、
失物招领 updateStatus、二手 updateStatus。

## 四、性能与加载优化

### 1. 消除 N+1 查询（`ChannelController.postList`）

**问题**：循环里对每条帖子各执行 2 次 `count()`（点赞数、评论数），
每页 10 条 = `1 + 10×2 = 21` 次查询，加上后续查询共 **22 条 SQL**。

**修复**：改为**批量聚合**——一次性查出所有点赞/评论记录，在内存用 `groupingBy` 统计。

**效果**：`22 条 → 4 条` SQL，响应 `91ms → 15ms`。

### 2. 新增 12 个复合索引（`sql/perf_indexes.sql`）

各列表接口的统一查询模式是：
`WHERE school_id=? AND status=? ORDER BY create_time DESC`

原有索引都是**单列**，MySQL 只能用到一列，另一列 + 排序要回表 / filesort。
新增复合索引 `(school_id, status, create_time)` 同时覆盖过滤与排序。

已用 `EXPLAIN ... FORCE INDEX` 验证命中，`Extra` 显示 **`Backward index scan`**，
即直接反向扫描索引，**消除了 filesort**。

脚本使用存储过程判断索引是否存在，**可重复执行、幂等**。

### 3. 首屏请求并行化（`pages/index/index.vue`）

**问题**：首页综合数据与活动列表是**互相独立**的两个请求，原先串行 `await`，
总耗时 = 两者之和。

**修复**：改 `Promise.all` 并行，总耗时 ≈ 较慢的那个；活动列表失败不再影响首屏。
同时把重复定义 3 次的模块列表抽成 `ALL_MODULES` 常量。

### 4. 请求层加固（`utils/request.js`）

- **loading 计数器**：并发请求原先各自 `showLoading`/`hideLoading`，先返回的会把遮罩提前关掉造成闪烁 → 改为计数器，最后一个结束才关闭。
- **GET 请求去重**：相同 URL+参数在飞行中复用同一 Promise，避免重复网络开销。
- **保留原有 GET 自动重试**，并确保去重表在成功/失败后都清理。

## 七、重要说明

### 1. 关于工作区权限问题（需你留意）

排查中发现：**工作区根目录可以写入，但所有既有的子目录（backend、frontend、sql…）都无法写入**。

原因：这些子目录的 Windows 文件权限项与完整性标签，是 DSH 沙箱建立
**工作区授权之前**就已存在的，没有继承到沙箱要求的授权项。
（确切机制：根目录有 `S-1-4-…` 授权项和 `Low` 完整性标签，而既有子目录都没有。）

**这会影响你之后的开发**（IDE 之外的命令行工具可能无法写入项目目录）。
本次我采用的绕过方式：把源码同步到 `.build/proj` 下用 Maven 构建。
`.build/` 是本次新增的临时目录，可随时删除；**源文件都在原位置，未受影响**。

如需彻底修复，可在**完全权限**模式下运行 ACL 诊断脚本，或手工给
`D:\Self_Project\Demo\SmartCampus` 的子目录补上继承权限。

### 2. 状态码语义提醒（潜在坑）

`errand_order.status` 的**建表注释**与**代码/前端实际使用**不一致：

- 建表注释：`0:待接单 1:已接单 2:进行中 3:已完成 4:已取消`
- 实际使用：`0:已取消 1:待接单 2:进行中 3:已完成`

我**保持了代码现状**（因为前端 `adaptErrand` 的 `statusMap` 依赖它），
仅在代码里加了注释说明。若要统一，需同时改动前端映射，属破坏性变更。

### 3. 预留未实现接口

前端 API 层标注「后端暂无此接口」的有：商品收藏、更新商品、AI 失物匹配、
活动报名人员列表、打印价格配置等（部分已有后端实现但路径不一致）。
这些不影响现有功能，未在本次范围内改动。
