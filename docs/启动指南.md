# SmartCampus 启动指南

> 项目由三部分组成：**后端 API**、**用户端**（小程序/H5）、**管理后台**。
> 无论启动哪一端，**都必须先启动后端**。

## 二、第一步：启动后端（必须）

后端是用户端和管理后台共同依赖的基础。

### 方式 A：一键脚本（推荐）

双击项目根目录的 **`start-backend.bat`**

脚本会自动：
1. 切换到 JDK 21
2. 若有 `target/smart-campus-1.0.0.jar` 就直接启动，否则用 Maven `spring-boot:run`

### 方式 B：命令行

```powershell
cd D:\Self_Project\Demo\SmartCampus\backend

# 设定 JDK 21（关键！系统默认 java 是 1.8，会编译报错）
$env:JAVA_HOME = 'D:\code\get_jobs\jdk-21.0.10+7'

# 首次或改动代码后先打包
& 'D:\JAVA\ideaIC-2024.1.4.win\plugins\maven\lib\maven3\bin\mvn.cmd' clean package -DskipTests

# 启动
& "$env:JAVA_HOME\bin\java.exe" -jar target\smart-campus-1.0.0.jar
```

### 方式 C：IDEA 里直接运行

在 IDEA 中打开 `backend` 目录，把 **Project SDK 设为 JDK 21**，运行 `SmartCampusApplication` 即可。

### 验证后端启动成功

```
浏览器打开 http://localhost:8080/doc.html        # 接口文档（Knife4j）
或访问 http://localhost:8080/api/school/list      # 应返回 {code:200,...}
```

> 启动日志出现 `Started SmartCampusApplication` 即成功。
> 若报 `Port 8080 was already in use`，说明已有一个实例在跑，先停掉再启动。

## 三、第二步：启动用户端

用户端是 **uni-app（Vue3）** 工程，在 `frontend/` 目录，
**一套代码可编译成 H5 网页 / 微信小程序 / App**。

### 3.1 启动 H5（浏览器里调，最方便）

**一键脚本**：双击 **`start-user-h5.bat`**

**命令行**：
```powershell
cd D:\Self_Project\Demo\SmartCampus\frontend
npm install       # 首次运行
npm run dev:h5    # 或 npm run dev
```

访问 **http://localhost:5173**

> H5 模式下 `request.js` 使用相对路径 `/api`，由 Vite 代理转发到 8080，
> 因此**不需要处理跨域**（代理已在 `vite.config.js` 配好）。

### 3.2 启动微信小程序

**一键脚本**：双击 **`start-user-mp.bat`**

**命令行**：
```powershell
cd D:\Self_Project\Demo\SmartCampus\frontend
npm run dev:mp-weixin      # 开发模式（监听文件变更）
# 或 npm run build:mp-weixin   # 一次性构建
```

然后用**微信开发者工具**导入这个目录：

```
D:\Self_Project\Demo\SmartCampus\frontend\dist\build\mp-weixin
```

**必须设置**（否则请求全部失败）：
> 微信开发者工具 → 右上角「详情」→「本地设置」→
> 勾选 **「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」**

原因：小程序端 `request.js` 里 `BASE_URL = 'http://localhost:8080'`，
而微信默认只允许 `https` 且已备案的域名，本地调试必须关掉域名校验。

### 3.3 关于 `miniprogram/` 目录

项目根目录还有一个 `miniprogram/`，那是**早期的原生微信小程序版本**，
只有 8 个页面（首页、二手、校园圈、失物招领、我的），功能远少于 `frontend/`。

**建议以 `frontend/` 为准**——它有 39 个页面，覆盖全部业务模块。
`miniprogram/` 可视为历史遗留，除非你明确要维护那个版本。

## 四、第三步：启动管理后台

管理后台是独立的 **Vue3 + Element Plus** 工程，在 `admin/` 目录。

**一键脚本**：双击 **`start-admin.bat`**

**命令行**：
```powershell
cd D:\Self_Project\Demo\SmartCampus\admin
npm install       # 首次运行
npm run dev
```

访问 **http://localhost:8081**

**默认账号**：`admin` / `admin123`

> 管理后台同样通过 Vite 代理 `/api` → 8080，无需处理跨域。

## 五、最简启动顺序（推荐）

日常开发只需要开两个窗口：

```
窗口 1:  start-backend.bat          → 后端 8080（必须先起）
窗口 2:  start-admin.bat            → 管理后台 8081
   或    start-user-h5.bat          → 用户端 H5 5173
```

如果你想**同时看用户端和管理端**，开三个窗口：

```
窗口 1:  start-backend.bat     后端      http://localhost:8080
窗口 2:  start-user-h5.bat     用户端    http://localhost:5173
窗口 3:  start-admin.bat       管理后台  http://localhost:8081
```

**登录用的测试账号**

| 端 | 账号 |
|---|---|
| 管理后台 | `admin` / `admin123` |
| 用户端 | 任意 11 位手机号（如 `13800001234`），验证码会直接返回在页面上（模拟短信） |

## 六、生产部署（H5 + Nginx）

若要把 H5 部署到 Nginx（项目已含 `nginx-1.24.0/`）：

```powershell
# 1. 构建 H5
cd frontend
npm run build:h5
# 产物在 frontend/dist/build/h5

# 2. 复制到 Nginx 的 html 目录
Copy-Item -Path dist\build\h5\* -Destination ..\nginx-1.24.0\html\ -Recurse -Force

# 3. 启动 Nginx
cd ..
.\start-nginx.bat
```

访问 **http://localhost/**（Nginx 同时反代 `/api` 到 8080，见 `nginx.conf`）

## 七、常见问题

| 现象 | 原因与解决 |
|---|---|
| 后端起不来，报 `无效的标记: --release` 或语法错误 | 用了 JDK 1.8。**必须设 `JAVA_HOME` 为 JDK 21**（脚本已自动定位） |
| `Port 8080 was already in use` | 已有实例在跑。先 `netstat -ano \| findstr :8080` 找到 PID 后结束进程 |
| 前端页面数据全是空的 | 后端没启动。先确认 `http://localhost:8080/api/school/list` 能返回 |
| 小程序请求全部失败 | 微信开发者工具未勾选「不校验合法域名」 |
| 管理后台登录失败 | 后端没起或账号密码不对（`admin`/`admin123`） |
| `npm run build` 报 esbuild `Access is denied` | 管理后台已在 `vite.config.js` 内处理（临时目录指向 `.tmp-esbuild/`） |
| Redis 报 `NOAUTH Authentication required` | Redis 需要密码。`application.yml` 中已配 `password: 123456` |
| 用户端 H5 修改后不生效 | Vite 有热更新；若异常，重启 `npm run dev:h5` |
| **改动源码后构建仍报旧错误** | **Vite 缓存**。删掉 `frontend/node_modules/.vite` 后重新构建 |
| `.bat` 脚本中文乱码 | 见下方「关于脚本编码」 |

### 关于脚本编码（重要）

所有 `.bat` 脚本都以 **GBK(936) 编码 + CRLF 换行** 保存。
这是中文 Windows 上 `cmd.exe` 的默认代码页，能保证双击运行时中文正常显示。

> ⚠️ **不要用 VSCode 等编辑器把 `.bat` 另存为 UTF-8**，否则会乱码，
> 甚至导致命令解析失败。如果必须编辑，请把编码保持为 `GB2312/GBK`。
>
> 作为对比：`.md` / `.java` / `.js` / `.vue` 等源码文件统一用 **UTF-8**，这是正确的。

### 关于 Vite 缓存

`uni-app` / `Vite` 会把编译结果缓存在 `node_modules/.vite`。
极少数情况下（例如批量改动源码后立刻构建），可能读到旧缓存并报出**已经修好的错误**。
若遇到"错误指向的代码明明已经改了"，执行：

```powershell
Remove-Item -Recurse -Force frontend\node_modules\.vite
# 管理后台同理
Remove-Item -Recurse -Force admin\node_modules\.vite
```

然后重新构建即可。
