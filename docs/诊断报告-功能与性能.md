# SmartCampus 全量功能测试与根因诊断报告

> 测试环境：Windows + JDK21 + Spring Boot 2.7.18 + MySQL 8.0.45 + Redis 6
> 数据库：`smart_campus`（真实活库，`sql_mode` 含 `STRICT_TRANS_TABLES`）
> 测试方式：以**前端真实调用方式**逐个请求全部业务接口（HTTP 实测）

---

## 一、总体结论

实测 **25 个核心接口，21 个失败，仅 4 个正常**。

| 类别 | 数量 | 现象 |
|---|---|---|
| 发布类接口 | 7 个 500 | 服务器内部错误 |
| 接取/操作类接口 | 14 个 400 | 参数绑定失败 |
| 正常 | 4 个 | substitute/goods/post/activity 的 create |

---

## 二、根因 A：接取类接口 400 —— `@RequestParam` 与 JSON body 不匹配

### 现象（实测）
```
POST /api/errand/acceptOrder   body={"id":1}   → HTTP 400
POST /api/errand/acceptOrder?id=1              → HTTP 200   ← 同一个接口，仅传参方式不同
```

### 根因
- 后端 14 个操作类接口声明 `@RequestParam Long id`（**只接受 query/form 参数**）
- 前端 `frontend/src/utils/request.js` 统一以 `Content-Type: application/json` + **JSON body** 发送
- 二者不匹配 → Spring 抛 `MissingServletRequestParameterException` → 400

日志实证：
```
MissingServletRequestParameterException: Required request parameter 'id' for method parameter type Long is not present
```

### 受影响接口（全部 400）
| 模块 | 接口 |
|---|---|
| 跑腿 | acceptOrder / completeOrder / cancelOrder |
| 快递 | pickOrder / completeOrder / cancelOrder |
| 代课 | acceptOrder / cancelOrder |
| 打印 | cancelOrder |
| 活动 | signup / cancelSignup |
| 频道 | likePost |
| 失物招领 | updateStatus |
| 二手 | updateStatus |

---

## 三、根因 B：发布类接口 500 —— 字段缺失 / 类型不匹配

### B1. 必填字段未提供（MyBatis-Plus 忽略 null + MySQL 严格模式）

MyBatis-Plus 默认 `NOT_NULL` 策略会**省略 null 字段**，严格模式下该列又无默认值 → 报错。

| 模块 | 缺失字段 | 实测报错 |
|---|---|---|
| 跑腿 errand | `receiver_name`、`total_amount` | Field 'receiver_name' doesn't have a default value |
| 快递 express | `total_amount` | Field 'total_amount' doesn't have a default value |
| 打印 print | `file_urls`、`delivery_address`、`receiver_name`、`receiver_phone`、`total_amount` | 全部 5 个 |
| 游戏搭子 game | `title` | Field 'title' doesn't have a default value |

打印模块还叠加**字段名写错**（Jackson 默认忽略未知字段，静默丢弃）：
`fileUrl`→应为 `fileUrls`、`address`→`deliveryAddress`、`phone`→`receiverPhone`、`price`→`totalAmount`

### B2. 字符串写入 TINYINT 列（MySQL 1366）

| 模块 | 字段 | 前端发送 | 列类型 | 实测报错 |
|---|---|---|---|---|
| 打印 print | `print_type` | `'document'` | TINYINT | Incorrect integer value |
| 失物招领 lostfound | `type` | `'lost'` | TINYINT | Incorrect integer value |
| 意见反馈 feedback | `type` | `'suggestion'` | TINYINT | Incorrect integer value |
| 聊天 chat | `msg_type` | `'text'` | TINYINT | Incorrect integer value |

### B3. 外键约束冲突（评论）
`comment.parent_id` 默认值为 `0`，但存在外键 `fk_comment_parent → comment(id)`，不存在 id=0 的行：
```
Cannot add or update a child row: a foreign key constraint fails (`fk_comment_parent`)
```
实测 `INSERT ... parent_id=0` → `ERROR 1452`。

## 四、根因 C：发布后数据不可见（业务逻辑矛盾）

| 模块 | create 写入 | list 过滤 | 结果 |
|---|---|---|---|
| 活动 activity | `status=0`（注释写"待审核"） | `status=1` | **发布后列表看不到** |
| 失物招领 lostfound | `status=0` | `status=1` | **发布后列表看不到** |

`activity.status` 语义实为 `0:已结束 1:报名中 2:进行中`，审核应使用 `audit_status`（另有该列）。

---

## 五、根因 D：无全局异常处理

项目**没有** `@RestControllerAdvice`，任何数据库异常都直接抛原始 500 JSON，前端
`request.js` 只能显示笼统的「服务器开小差了」，无法定位问题。

---

## 六、性能与加载问题

| 问题 | 位置 | 影响 |
|---|---|---|
| **N+1 查询** | `ChannelController.postList` 每条帖子 2 次 count（点赞/评论） | 10 条帖子 = 1+20 次查询 |
| 分页无总量优化 | 多处 | — |
| 前端无请求去重/缓存 | `utils/request.js` | 重复请求 |
| 首页串行请求 | `pages/index/index.vue` | 首屏变慢 |

实测响应时间（本地，数据量小）：
`/home/noticeList` 102ms、`/channel/postList` 91ms 明显高于其他（后者即 N+1）。

---

## 七、修复方案

1. **参数兼容层**：新增 `ParamResolver`，让操作类接口**同时兼容** query 参数与 JSON body（向后兼容 Swagger/小程序/curl）。
2. **服务端补全**：`totalAmount` 由服务端按 `serviceFee+goodsFee+tip` 计算，杜绝漏传。
3. **类型归一**：字符串枚举（lost/found、suggestion、text、document）在服务端统一映射为数字，前端也改为发送数字。
4. **外键修复**：`parentId` 为 0/null 时置为 null。
5. **可见性修复**：修正 create 与 list 的状态语义矛盾。
6. **全局异常处理**：新增 `GlobalExceptionHandler`，统一返回 `{code,msg}`，前端可展示真实错误。
7. **性能优化**：消除 `postList` 的 N+1，改为批量聚合查询。
